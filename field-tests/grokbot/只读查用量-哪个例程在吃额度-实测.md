# 只读查用量：到底是谁在吃额度？（实测）

- 来源：用法本身是 Grok Bot 的现成功能：在对话里直接问 Bot“本周额度用了多少、哪个例程/哪个 Bot 用得最多”。起因是我们自己开了一批每小时例程，想知道它们是不是在吃额度。
- 状态：**实测**（2026-11-09 16:21–16:23 EST，同一账号三次只读查询）。公开要点见 [evidence/usage-readonly/summary-public.md](evidence/usage-readonly/summary-public.md)。当时只照抄了要点，没有存原始报告。
- 隐私口径：套餐名、额度百分比、重置时刻、各例程和各 Bot 的名字与占比都是账号私人用量数据，本文不写，只写结构性结论。
- 风险：只读，不改任何设置、不花钱。

## 步骤
1. 问“本周用量按例程分”。
2. 问“近 7 天按活动类型（聊天/例程/Bot对Bot/群聊）分”。
3. 问“本周按 Bot 再按活动分”。

## 实测结果（一个账号，当时开着 8 个例程：6 个每小时；2 个是观察例程 A/B，按 cron `CRON_TZ=America/New_York 0 8,11,14,17,20 * * *` 美东 8–20 点每 3 小时一次（每天 5 次），一周约 35 次，cron 原文见 [cron-source.txt](evidence/routine-punctuality/cron-source.txt)）
- 三次查询都调用成功，各自返回了分项份额。
- 所有例程合计只占很小一部分（个位数百分比），绝大部分用量不是来自例程。
- 按活动分：和 Bot 直接聊天约占一半；Bot 之间互相派活和群聊合计占四成多；例程最少。

## 结论（只对这个账号、这一个时间点成立）
- **定时例程不是大头**：这次真正吃额度的是和 Bot 直接聊天，以及多个 Bot 之间互相派活和群聊。
- 想省额度，先看“多 Bot 互相聊”和与 Bot 的直接聊天，再看定时任务。
- **不能外推**：例程每轮做多少事差别极大；跑得更久以后例程占比可能上升。之后可再查一次对比。

## 坑
1. 报告里的“约 N 次/周”是按计划推算的频率，不是已经跑了多少次。
2. 百分比是“占全部 Grok Bot 用量的份额”，不是“占额度的百分比”。要换算成占额度多少，得自己乘（推测，报告本身没给这个数）。
3. 份额四舍五入，很多显示“<1%”，没法细比哪个例程更贵。
4. 更早的周只给占比，看不到当周额度用了多少。
5. 额外用量余额这里看不到，要去设置页。
6. 已删除的 Bot、群聊和他人的 Bot 会合并成一行（报告原文是“已删除的Bot/群聊/他人的Bot”），无法再追是哪一个。

## 复现难度
低：任何用户在对话里问一句即可，不需要连接器。

## 诚实边界
- 只有一个账号、一个时间点的样本（n=1）。
- 没有存原始报告，只有当时的要点摘录（内部存档）。
- 没有测“例程每轮做多少事”与耗量的关系。
